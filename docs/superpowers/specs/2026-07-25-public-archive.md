# 전체 공개 아카이브 설계

## 배경

현재 사이트는 `원문 제외 아카이브`, 잠금 아이콘, `visibility`, `consentChecked`, `available` 필드로 원문과 일부 인물 정보를 숨긴다. 사용자는 아이디어 기록과 제공한 원문뿐 아니라 실명도 공개해도 된다고 명시했다.

## 공개 정책

- 아이디어명, 설명, 당시 판단, 교훈, 판정자 실명을 공개한다.
- 사용자가 제공했거나 공개 저장소에 복사할 수 있는 원문은 사이트에서 바로 연다.
- Notion의 아이디어 페이지 본문은 정적 Markdown 공개본으로 보존한다.
- 로컬에 존재하는 `검은 항구` 룰북은 정적 공개 문서로 복사한다.
- 아직 원본을 확보하지 못한 첨부파일은 잠그지 않고 `원본 미수집`이라고 사실대로 표시한다.
- 제안일, 중단일, 중단 근거처럼 확인되지 않은 사실은 공개 여부와 무관하므로 `확인 필요`를 유지한다.
- 존재하지 않는 URL이나 확인하지 않은 판단 근거는 만들지 않는다.

## 데이터 구조

`Artifact`는 공개 여부가 아니라 실제 연결 가능 여부만 표현한다.

```ts
interface Artifact {
  name: string
  type: "pdf" | "md" | "zip" | "notion"
  url?: string
  note?: string
}
```

`Idea`에서 `visibility`와 `consentChecked`를 제거한다. 모든 레코드는 공개 데이터라는 단일 정책을 따른다.

## 화면 동작

- 상단의 `원문 제외 아카이브`를 `전체 공개 아카이브`로 바꾼다.
- 공개 URL이 있는 보존 자료는 새 탭에서 열리는 링크로 표시한다.
- URL이 없는 자료는 잠금 아이콘 없이 `원본 미수집` 상태로 표시한다.
- 상세 화면의 공개 동의 경고와 잠금 아이콘을 제거한다.
- 하단 문구는 아이디어와 제공 원문을 공개 보존한다는 정책으로 바꾼다.
- 공개 자료 링크 수는 데이터에서 계산한다.

## 문서 공개본

- `public/documents/notion-ideas.md`: 연결된 Notion `아이디어` 페이지의 본문 공개본
- `public/documents/black-harbor-rulebook.md`: 로컬 검은 항구 룰북 공개본

Notion 내부 첨부 토큰은 공개 URL이 아니므로 파일명과 미수집 상태만 남긴다. 실제 PDF가 확보되면 별도 정적 파일로 추가한다.

## 검증

- UI 테스트는 공개 배지, 원문 링크, 잠금 경고 제거를 확인한다.
- 데이터 테스트는 비공개 필드가 없고 모든 아이디어에 최소 하나의 공개 원문 링크가 있음을 확인한다.
- 전체 Vitest와 production build를 실행한다.
- 공개 문서 링크가 build 산출물에 포함되는지 확인한다.
