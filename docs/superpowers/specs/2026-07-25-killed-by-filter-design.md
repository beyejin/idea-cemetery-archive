# Killed by 판정자 필터 설계

## 목표

아이디어가 중단된 이유와 별개로, 누가 최종 중단 판단에 영향을 주었는지 기록한다. 첫 적용 대상은 `검은 항구`와 `팩매치`다. 공개 화면에는 각각 `KILLED BY 성원 튜터님`, `KILLED BY 밤송이클럽`로 표시한다.

## 범위

- 기존 정적 JSON 아카이브 구조를 유지한다.
- `Idea`에 단일 판정자 필드 `killedBy: string | null`을 추가한다.
- `검은 항구`와 `팩매치`를 16·17번째 기록으로 추가한다.
- `검은 항구`의 `killedBy`는 `성원 튜터님`, `팩매치`의 `killedBy`는 `밤송이클럽`로 설정한다.
- 기존 15개 기록의 판정자는 추측하지 않고 `null`로 둔다.
- 등록·수정 화면이나 서버 저장 기능은 만들지 않는다. 이후 기록은 팀원이 `ideas.json`을 수정해 추가한다.

## 검은 항구 공개 요약

- 제목: `검은 항구`
- 기준 자료: 사용자가 대화에서 제공한 `2.3-playtest` 5분 룰북. 4인, 8라운드, 25~35분 구성이다.
- 한 줄 설명: 4명이 화물 2개에 동시에 봉인 입찰하고, 시장 거래·비밀 계약 배송·밀수와 세관 조사를 거쳐 가장 높은 점수를 겨루는 웹 전략 게임.
- 제안일·중단일: 확인되지 않았으므로 `null`
- 중단 원인: `튜터 피드백`
- 당시 판단: 성원 튜터님의 피드백을 계기로 최종 프로젝트 후보에서 제외되었으며, 구체적인 판단 근거는 추가 확인이 필요하다고 기록한다.
- 남은 교훈: 이중 봉인 경매와 비밀 계약의 게임성뿐 아니라, 여섯 단계와 8라운드를 팀 일정 안에 실제로 완주할 수 있는 구현 범위를 함께 검증해야 한다고 기록한다.
- 사용자가 제공한 룰북은 요약의 근거로만 사용하고 전체 원문과 구현 링크는 공개 번들에 넣지 않는다.

## 팩매치 공개 요약

- 제목: `팩매치`
- 기준 자료: 사용자가 첨부한 `팩매치 서비스 및 백엔드 기획서`.
- 한 줄 설명: 같은 생활권의 1인 가구가 필요한 상품과 수량을 등록하면 시스템이 수요를 자동으로 묶고, 성사된 수량만 결제해 고정 거점에서 수령하게 하는 무호스트 공동 장보기 플랫폼.
- 제안일·중단일: 확인되지 않았으므로 `null`
- 중단 원인: `팀 선택`
- 당시 판단: 밤송이클럽의 팀 논의 결과 최종 프로젝트 후보에서 제외되었으며, 구체적인 탈락 사유는 추측하지 않고 추가 확인이 필요하다고 기록한다.
- 남은 교훈: 동시성 안전한 수요 매칭과 결제 정합성을 구현하기 전에 제한된 생활권의 수요 밀도와 픽업 운영 가능성을 먼저 검증해야 한다고 기록한다.
- 첨부 기획서는 요약의 근거로만 사용하고 전체 원문은 공개 번들에 넣지 않는다.

## 화면

기존 검색과 `중단 원인` 선택 옆에 `Killed by` 단일 선택 필드를 둔다. 기본값은 `전체 판정자`이며 옵션은 현재 데이터에 실제로 존재하는 판정자만 중복 없이 만든다. 초기 옵션은 `성원 튜터님`, `밤송이클럽`이다.

검색어, 중단 원인, 판정자는 AND 조건으로 함께 적용한다. `검색과 필터 초기화`는 세 값을 모두 초기화한다.

판정자가 있는 기록은 목록 본문에 `KILLED BY …` 표식을 보여 주고, 상세 다이얼로그에도 `Killed by` 항목을 표시한다. 판정자가 없는 기록에는 빈 표식이나 `미상`을 추가하지 않는다. 기존 색상, 타이포그래피, 2열 목록 형식은 유지한다.

## 개인정보 문구

사용자는 2026-07-25에 `성원 튜터님`과 `밤송이클럽`이라는 표시를 공개 사이트에 노출하도록 요청했다. 기존의 `인물 정보는 표시하지 않습니다` 문구는 실제 동작과 맞도록 `공개 동의를 확인한 정보만 표시합니다`로 바꾼다. 다른 이름은 별도 확인 없이 추가하지 않는다.

## 오류와 빈 결과

선택한 판정자와 다른 필터가 함께 적용되어 결과가 없으면 기존 빈 결과 화면을 그대로 사용한다. 데이터에 없는 판정자 옵션은 만들지 않는다.

## 테스트 경계

테스트는 사용자가 실제로 접하는 두 공개 경계에 둔다.

1. `App` 경계: `Killed by` 선택 필드에서 판정자를 고르면 해당 기록만 남고, 카드와 상세 화면에 판정자 표식이 보이며, 초기화하면 전체 17개 기록이 돌아온다.
2. 데이터 경계: 모든 기록의 `killedBy`가 문자열 또는 `null`이고, `검은 항구`와 `팩매치`에 승인된 판정자가 연결된다.

각 동작은 실패하는 테스트를 먼저 확인한 뒤 최소 구현으로 통과시킨다.

## 완료 조건

- 전체 기록 수가 17개다.
- `Killed by` 필터, 카드 표식, 상세 정보가 키보드와 스크린 리더에서 구분된다.
- 기존 검색·중단 원인 필터·다이얼로그 동작이 유지된다.
- 전체 테스트와 프로덕션 빌드가 통과한다.
- `main` 소스와 `gh-pages` 배포를 갱신하고 공개 URL에서 새 기능을 확인한다.
